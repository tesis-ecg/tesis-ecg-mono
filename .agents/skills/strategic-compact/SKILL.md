---
name: strategic-compact
description: Preserve continuity when a long session approaches its context limit or reaches a useful compaction boundary. Use real context indicators and task state, not a count of file edits.
---

At a meaningful boundary, summarize the objective, current state, decisions, relevant paths, verification and next step in chat. Suggest the runtime's available compaction control when useful; do not assume identical slash-command arguments in every client.

After compaction, proactively restate what is done, what remains and where artifacts live in 2–3 lines, then continue. Do not claim that a fixed list of transient state always survives compaction.

Offer a handoff file if losing context would prevent safe continuation, but create it only when requested. Avoid reminders based solely on edit counts, and do not interrupt implementation repeatedly.
